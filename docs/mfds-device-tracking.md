# 국내 의료기기 인허가 추적 설계

검토일: 2026-11-11. 현재 단계: **공식 API 명세 확인·오프라인 테스트 완료, 실데이터 연결 전**.

## 공식 원천 및 연결

- [식약처 의료기기 품목허가 정보, 공공데이터포털 15057456](https://www.data.go.kr/data/15057456/openapi.do)
- 원문 설명: 무료, 이용허락 제한 없음, 갱신주기 실시간. 실시간 표기는 모든 개별 변경이 즉시 관측된다는 SLA가 아니다.
- 원문 상세/Swagger를 확인한 기본 URL: `https://apis.data.go.kr/1471000/MdlpPrdlstPrmisnInfoService06`
- 목록: `/getMdlpPrdlstPrmisnList05` (업체명 `entrps` 등 소문자 필터)
- 상세: `/getMdlpPrdlstPrmisnItem05` (업체명 `ENTRPS`, 모델 `TYPE_NAME`, 사업자번호 `BRNO` 등 대문자 필터)
- 공공데이터포털 인증키 `serviceKey`가 필수. 해당 서비스의 활용신청 승인이 필요하다. 다른 공공데이터 API가 작동한다고 이 서비스 이용 승인이 확인되는 것은 아니다.
- 검토한 공식 페이지상 개발계정 트래픽 10,000, 개발·운영 자동승인. 신청 시 현재 조건을 다시 확인한다.
- 권장 저장소 Secret 이름: `MFDS_DEVICE_API_KEY`. 키는 브라우저 JS·JSON·소스·채팅에 넣지 않고 서버 작업에만 공급한다.
- 현재 로컬에는 이 이름의 키가 없고 이번 수정 전 APR 수집/워크플로에는 MFDS 연계가 없었다. **저장소 Secret 존재 여부는 확인하지 않았다.** 실제 인증 및 데이터 수집 성공을 아직 검증하지 않았다.

수정안에는 `mfds_device_registry.py`, 신사업 탭의 상태/등록정보 패널, 기존 아침 갱신 작업의 선택적 수집 단계를 포함했다. 키 미등록 시 네트워크 호출 없이 `not_configured`로 남는다. 아직 원격 병합·배포·실제 API 연결 성공을 확인한 것은 아니다.

## 무엇을 추적할 것인가

1. 에이피알과 에이피알팩토리 업체명으로 상세 목록을 모두 조회한다. 초기 회사명 후보는 관련 공시·사업자번호로 확인한다.
2. 공식 APR 홈페이지에 표시된 에이피알 사업자번호 `220-88-89441`은 정확 일치 판정에 사용한다. 에이피알팩토리의 사업자번호는 아직 독립 확인되지 않아 이름 일치만으로 확정 동일법인 처리하지 않는다.
3. 업체명 변경·합병·양수도는 품목 일련번호를 중심으로 같은 품목인지 비교한다. `에이지알/AGE-R`는 브랜드·제품군 이름과 겹치므로 이 문자열만으로 APR 제조품을 확정하지 않는다.
4. 품목허가번호, 품목명/모델, 등급, 사용목적, 업체/제조자/제조의뢰자, 허가일, 변경일, 취소취하 코드/일시를 저장한다.
5. `허가일`, `공공등록부 변경일`, `처음 관측한 날`, `마지막 성공 조회일`은 다른 날짜다. 첫 조회의 과거 품목은 기준 목록만 만들며 신규 허가 알림으로 쓰지 않는다.
6. 이후의 새 행은 **새로 발견한 등록정보**, 상태/필드 변화는 **등록정보 변경**으로 표시한다. 새로운 승인인지 여부는 원문 허가일과 변경 내용을 확인한 뒤 판단한다.
7. 사라진 행은 이전 값을 유지하고 재확인 대상으로 둔다. 목록 누락을 허가 취소로 추정하지 않는다. 취소취하 코드의 공식 값 사전은 추가 확인 전 원문 그대로 표시한다.
8. 심사 중 신청, 보완 요구, 예상 승인일은 이 공개 허가 등록부로 확인할 수 없다. IR/회사 발표는 별도 **회사 설명** 증거로만 연결한다.

## 국내 판매 승인과 수출전용 허가를 구분

API 상세 명세에는 수출전용 여부를 명시하는 필드가 확인되지 않았다. 등급, 한국 허가번호, 식약처 등록 사실만으로 **국내 판매 가능**을 자동 판정하지 않는다. 해당 허가 원문/공식 상세에 근거해 사람이 확인한 범위를 별도 저장해야 한다.

[APR 2026-10-15 공식 발표](https://apr-blog.com/medicube-skinbooster)는 다음 두 제품을 구분한다.

- AGE-R: 점착성 투명 창상피복재, 2등급 관련 인증으로 설명.
- AGE-R PLUS G: 조직 수복용 생체 재료, **수출용 4등급 허가**로 설명.

이 발표의 허가번호·일자를 규제 원문에서 독립 확인한 것은 아니다. 따라서 위 설명을 실데이터 행으로 심지 않는다. 회사는 국내 제품 개발·인허가 진행 계획을 별도로 설명한다. 수출 허가를 국내 승인으로 바꾸거나 칠레 출시를 국내 승인으로 해석하면 안 된다.

품목허가·인증·신고, 의료기기 제조업허가, GMP 적합인정, 임상시험 승인, 해외 허가, 출시/매출은 서로 다른 사건이다. 홈뷰티 제품이 이 등록부에서 보이지 않는다는 사실만으로 불법/무허가라고 해석하지 않는다.

## 화면과 상태 설계

신사업 영역에 국내 인허가 표를 추가하되 다음을 독립 표시한다.

- 규제기관 원문 확인 / 회사 발표만 확인 / 검증 대기
- 국내 사용 범위 확인 / 수출전용 확인 / 범위 미확인
- 현재 품목 상태, 원문 허가일/변경일, 최초 관측일, 마지막 성공일
- API 미연결 / 권한 문제 / 조회 실패 / 정상 전체조회

숫자 0은 성공한 전체조회에서 관측된 행이 0개였다는 뜻으로만 사용할 수 있다. 그 경우에도 APR 전체 미허가를 뜻하지 않는다. 실패나 미연결에는 미확인으로 표시한다. 승인·출시는 매출 실현을 보장하지 않는다.

## 수집 운영

- 키와 서비스 권한 확인 후 최초 1회 수집, 원문 회사 식별/상태 코드/범위를 대조한다.
- 기존 07:30 KST 부근 아침 예약 실행에 하루 한 번 연결한다. GitHub 예약 실행은 지연될 수 있다. 키 설정 후 이 단계는 무료 MFDS API만 사용한다. 사용자가 계속 추적된다고 믿기 전 실제 배포·키 연결·성공 실행을 검증한다. 전체 workflow_dispatch는 기존 다른 수집도 함께 실행하므로, MFDS만 별도 검증하려면 승인된 `[mfds-now]` 코드 푸시 경로를 사용하거나 전용 실행 방식을 추가 검토한다.
- 매번 두 업체 전체 페이지를 조회한다. 날짜 필터만 쓰면 과거 허가의 상태 변경을 놓칠 수 있다.
- 최대 업체당 10페이지 × 100행, 기본적으로 하루 최대 20호출. 한도/페이지 수가 넘거나 조회 중 행 수가 달라지면 불완전 상태로 처리한다.
- 모든 업체 조회가 성공해야 현재 관측값을 교체한다. 부분 실패/403이면 이전 완전한 스냅샷을 보존하고 재시도나 다른 인증 경로 우회는 하지 않는다.
- 스냅샷은 `records`, 최근 실행 `events`, 최근 5,000건 `event_history`를 보유한다. 장기 이력은 Git 이력과 함께 보존한다.
- Secret을 포함할 수 있는 URL, 원본 예외 메시지, 응답 body는 공개 오류값에 기록하지 않는다.

## 시험과 미완료

- `python -m unittest tests/test_mfds_device_registry.py`: 합성 데이터 13개 회귀 테스트.
- `python -m unittest discover -s tests`: 기존 전체 테스트 포함.
- 명세에 맞춘 샘플만 사용했다. **실제 MFDS API 수집, 회사 식별 최종 검증, 국내/수출 범위 원문 검증, 운영 배포와 첫 예약 실행은 미완료.** UI/워크플로 코드는 준비했으나 아직 운영 활성화를 뜻하지 않는다.
- `node tests/smoke_mfds.cjs`: 미연결·실패·관측 상태, 동일 데이터 재조회, 출력 escaping, 배포 파일 포함 여부 검증.
- 기존 전체 JS smoke와 syntax 검사 통과. 실제 브라우저 시각 검사는 별도 확인 사항이다.
- 준비물: 수집 모듈, 비활성 상태 JSON, 신사업 UI, 선택적 무료 아침 수집 단계, 테스트, 본 문서. 규제 승인 여부를 주장하는 실제 데이터나 가짜 허가번호는 공개 데이터에 추가하지 않았다.
